Por qué este nombre

«Dedícalo Play» no es casual — cada palabra tiene peso.

El naming fue el primer reto estratégico. Necesitaba un nombre que:

  • Dedícalo: mantiene el equity de marca del ecosistema existente. Los usuarios que conocen Dedícalo.es (el producto de canciones personalizadas) entienden de inmediato el universo musical. No partimos de cero.
  • Play: tiene doble significado intencionado — play como reproducir música y play como jugar. Una sola palabra activa los dos pilares del producto: música y entretenimiento social.
  • play.dedicalo.es: el subdominio refuerza la jerarquía de marca. Es un hijo del ecosistema, no un proyecto ajeno. Esto mejora el SEO de dominio raíz y genera coherencia de marca.
"El nombre ideal para un producto musical y social no es el que describe lo que hace, sino el que genera la emoción correcta antes de abrirlo."

Análisis y proceso UX

Primero entendí el espacio. Luego diseñé la solución.

El proceso partió de un benchmark honesto: ¿qué juegos musicales existen, qué los hace adictivos y qué fricción generan? Solo después de entender el espacio competitivo tomé decisiones de diseño.

01
🔍
Benchmark competitivo

Analicé Kahoot, SongPop, Heardle y Quiz musical de Spotify. Detecté el patrón: todos requieren que el usuario adivine canciones ajenas. Nadie usaba la música propia como mecánica central.

Research
02
💡
Insight clave

La gente no quiere adivinar canciones genéricas — quiere compartir las suyas. La emoción más fuerte en un juego musical es que alguien adivine tu canción favorita. Ahí estaba la oportunidad.

Insight
03
🗺️
Journey map

Mapeé el flujo completo: desde que alguien propone jugar hasta que termina la partida. Identifiqué los 3 puntos de fricción críticos: crear sala, unirse sin cuenta y entender las reglas en segundos.

UX Research
04
⚡
Principio de diseño

Cero fricción en los primeros 30 segundos. El usuario debe poder unirse a una partida activa con solo un código de sala. Sin registro obligatorio en la entrada, sin tutorial largo, sin pantallas de carga.

Decisión UX
05
📱
Mobile-first estricto

El 100% de las partidas se juegan desde el móvil, en entornos ruidosos y con poca atención visual disponible. Cada elemento de UI debía ser funcional con el pulgar, grande y legible con música de fondo.

Contexto
06
🧪
Test con usuarios reales

Probé el prototipo en tres sesiones con grupos reales. El hallazgo más importante: los usuarios no leían instrucciones. Redesigné el flujo para que las reglas se enseñaran jugando, no explicando.

Testing

Mecánicas de juego

Tres pasos. Sin manual. Diversión inmediata.

El diseño de las mecánicas tuvo una restricción clara: cualquier persona que nunca haya jugado debe entender cómo funciona antes de que empiece la primera canción. La interfaz es el tutorial.

  • Paso 1 — Crear sala: el anfitrión crea una sala en segundos. El sistema genera un código PIN único de 6 dígitos y un QR compartible. No hace falta cuenta para unirse.
  • Paso 2 — Unirse y escuchar: los jugadores entran con el código, seleccionan una canción para dedicar y esperan el turno. La canción se reproduce en la sala de forma sincronizada.
  • Paso 3 — Votar y ganar: los jugadores votan qué canción prefieren y acumulan puntos. El ranking en tiempo real mantiene la tensión durante toda la partida.

Sincronización Spotify

La canción más honesta es la que ya tienes en tu lista.

La integración con Spotify fue la decisión técnica más importante del producto. No queríamos una base de datos de canciones genéricas — queríamos que cada jugador trajera su música real.

🔐
OAuth 2.0 con Spotify

El usuario autoriza el acceso a su cuenta Spotify mediante OAuth 2.0. Solo solicitamos el permiso user-read-currently-playing y user-top-read. Nunca almacenamos credenciales.

Seguridad
🎼
Biblioteca personal como fuente

El jugador elige la canción que quiere dedicar directamente desde sus playlists de Spotify. El sistema obtiene el preview de 30 segundos a través de la Spotify Web API y lo sincroniza en la sala.

API Integration
🔄
Reproducción sincronizada

Todos los jugadores de la sala escuchan el mismo fragmento al mismo tiempo. La sincronización usa Firebase Realtime Database para distribuir el timestamp de inicio con una latencia menor a 200ms.

Real-time

Catálogo de canciones

Google Sheets como fuente de verdad del catálogo.

Además de las canciones de Spotify, el juego cuenta con un catálogo curado de canciones predefinidas. La gestión de este catálogo usa Google Sheets como base de datos colaborativa, sincronizada automáticamente con la aplicación.

  • Estructura del Sheets: cada fila es una canción con columnas para título, artista, género, decade, URL de preview, imagen de portada y puntuación editorial.
  • Sincronización automática: una automatización en Make (Integromat) detecta cambios en el Sheets y actualiza la colección songs en Firestore sin intervención manual.
  • Control editorial sin código: el equipo puede añadir, eliminar o editar canciones desde el Sheets sin tocar el repositorio. El cambio se refleja en el juego en menos de 2 minutos.
  • Filtrado por sala: el sistema puede filtrar canciones por género o decade según el tipo de partida que configure el anfitrión (años 80, reggaeton, clásicos, etc.).

Stack técnico

Herramientas elegidas con criterio, no por moda.

Cada herramienta del stack tiene una justificación de negocio. No usé nada por tendencia: usé lo que resolvía el problema específico con el menor tiempo de implementación y el mayor impacto.

🔥
Firebase
Auth, Firestore y Realtime Database. La sincronización multijugador en tiempo real depende de Firebase RT DB. Firestore gestiona perfiles, historial de partidas y puntuaciones.
Core del producto
▲
Vercel
Despliegue continuo desde GitHub. Cada push a main genera un preview deployment automático. Las Edge Functions gestionan los endpoints de la Spotify API sin exponer claves.
Deploy & edge
🎵
Spotify Web API
Fuente de las canciones de los jugadores. OAuth 2.0 para autenticación, endpoints de playlists y tracks para la biblioteca personal, previews de 30 segundos para reproducción en sala.
Integración clave
🤖
ChatGPT / GPT-4o
Generación automática de metadatos de canciones (mood, etiquetas, descripción). También se usa para generar comentarios dinámicos del juego: frases personalizadas según el resultado de cada ronda.
IA aplicada
🎙️
Suno AI
Generación de canciones originales para el catálogo curado cuando no hay preview disponible en Spotify. También se usa para crear jingles del propio juego y efectos de transición entre rondas.

Automatizaciones

El producto funciona solo. El equipo diseña, no opera manualmente.

Diseñé el backend operativo para que no requiera intervención manual en las tareas repetitivas. Cada flujo de automatización tiene un propósito de negocio medible.

🗂️
Sheets → Firestore

Make detecta cambios en el catálogo de Google Sheets y sincroniza Firestore automáticamente. El catálogo siempre está actualizado sin redeploy.

🏷️
Etiquetado GPT

Al añadir canción nueva, Make llama a GPT-4o para generar mood, tags y descripción. Los metadatos enriquecidos se guardan de vuelta en Sheets y en Firestore.

🔔
Notificaciones de partida

Cuando se crea una sala con más de 4 jugadores, se dispara una notificación a los canales de difusión del producto con el código de sala para invitar a más jugadores.

📈
Métricas automáticas

Cada partida finalizada registra métricas en una hoja de Sheets: jugadores, duración, canciones más votadas y puntuaciones. Dashboard en tiempo real sin herramientas de analytics externas.

"Una automatización bien diseñada no solo ahorra tiempo — elimina errores humanos y permite que el producto escale sin contratar operadores."
